Платформа онлайн-квизов и тестирования на Oracle

Если вы впервые устанавливаете или проверяете проект, начните с
README_START_HERE.txt. Там находятся короткая инструкция
для университетского сервера и руководство для участника, автора и администратора.

Готовый учебный проект реализует требования на оценки 3, 4 и 5. Oracle Database хранит состояние и выполняет бизнес-логику, а нативное оконное приложение на Python/Tkinter запускается из изолированного venv, подключается к СУБД через одну общую учётную запись и вызывает пакет QUIZ_PLATFORM. Игроки регистрируются в самой игре. Браузер и локальный веб-сервер не используются.

Первый запуск на новом компьютере

Распакуйте всю папку проекта на диск с достаточным свободным местом (например, D:\OracleQuizArena), затем дважды щёлкните INSTALL_AND_RUN.cmd. Запускать файл из окна ZIP-архива нельзя.

Установщик для Windows x64 выполняет следующие действия:

1. Находит Python с Tkinter; если его нет, скачивает официальный Python 3.13.15 и устанавливает в .local/python-runtime рядом с проектом.
2. Создаёт или восстанавливает python/.venv, устанавливает зависимости. Повторно установленное не скачивается.
3. Находит Docker Desktop; если его нет, устанавливает WSL 2 и Docker Desktop. Новые файлы Docker и его диск данных размещаются на диске проекта. Windows может запросить права администратора и перезагрузку; после перезагрузки повторно запустите тот же файл.
4. Запускает локальную Oracle Free Lite. Образ скачивается только при отсутствии в кеше. Порт доступен только на 127.0.0.1:1521.
5. Генерирует локальные пароли, создаёт одну общую схему QUIZ_APP, устанавливает таблицы, пакет, игровые аккаунты и 24 демонстрационные игры, проверяет установку и открывает окно игры.

Нужны интернет для отсутствующих компонентов, Windows x64 с поддержкой Docker Desktop, включённая аппаратная виртуализация и свободное место для Oracle и Docker (несколько гигабайт). Если Docker уже установлен на другом диске, установщик не переносит его данные автоматически. При угрозе загрузки образа на C: он остановится и укажет настройку Docker Settings → Resources → Advanced → Disk image location. Общие системные компоненты Windows/WSL могут занимать место на системном диске.

Для уже доступного сервера Oracle (включая университетский), без загрузки Docker и образа БД:

На компьютере вуза дважды щёлкните INSTALL_UNIVERSITY_SERVER.cmd. Этот файл
сам включает режим существующей базы Oracle, поэтому параметры командной строки
вводить не требуется. Эквивалентная команда для терминала:

.\INSTALL_UNIVERSITY_SERVER.cmd

Используется python/.env; если подключения ещё нет, программа запросит хост, порт, SID/Service name, имя владельца схемы и пароль. Владельцу нужны права создания объектов и квота, перечисленные ниже. Установщик не удаляет существующие данные. При частично установленной схеме он сообщает об ошибке вместо автоматического удаления таблиц.

Команда INSTALL_AND_RUN.cmd -CheckOnly показывает найденные компоненты без установки. Параметр -NoLaunch завершает проверку без открытия окна. Для следующих запусков с локальной базой можно пользоваться тем же INSTALL_AND_RUN.cmd; когда Oracle уже работает, достаточно START_GAME.cmd.

При переносе исходников не копируйте .local, python/.venv, python/.env, .git и pycache: среда и локальные пароли создаются на новом устройстве. Готовый архив исходников можно собрать командой python\.venv\Scripts\python.exe package_release.py; результат — dist/OracleQuizArena.zip.

Источники параметров установки: Python для Windows (https://docs.python.org/3.13/using/windows.html), Docker Desktop для Windows (https://docs.docker.com/desktop/setup/install/windows-install/), официальный образ Oracle Free Lite (https://docs.oracle.com/en/database/oracle/agent-memory/26.6/guide/run-locally.html).

Данные для сдачи

Начальная установка включает пять игровых аккаунтов: администратора, автора, студента и двух игроков с историей. Это записи QP_USERS; отдельные пользователи СУБД для них не создаются.

- DEMO_ALICE / DemoAlice123! — 12 сохранённых игр.
- DEMO_BOB / DemoBob123! — 12 сохранённых игр.

У каждого игрока по четыре попытки обычного теста, адаптивного теста и командного квиза. Представлены все семь типов вопросов, правильные и ошибочные ответы, досрочное завершение и истечение времени. История создана демонстрационным сценарием, а не реальными пользователями: sql/06_demo_history.sql вызывает игровой PL/SQL API, который сохраняет ответы, начисляет баллы, формирует рейтинги, бейджи и PDF. Для сценария тайм-аута скрипт переносит дедлайн в прошлое и вызывает обычную проверку времени в Oracle.

Войдите под одним из этих логинов и откройте «Мои результаты», «Рейтинги», «Достижения и команды». Сохранены именно игровые попытки (QP_ATTEMPTS), а не только сессии авторизации. Все 24 попытки имеют PDF-сертификаты.

Скрипт истории включён в sql/install.sql. Повторная установка сверяет метки DEMO_HISTORY_V1 в журнале и не дублирует игры. Проверка требований находится в tests/verify_demo_history.sql; интеграционный тест tests/installer_integration_test.py разворачивает пустую временную схему, проверяет повторный запуск и удаляет только созданную им тестовую схему.

Что реализовано

- конструктор тестов и семь типов вопросов: один ответ, несколько ответов, текст, верно/неверно, число, упорядочивание и сопоставление;
- доступ к закрытым тестам по списку зарегистрированных игроков;
- регистрация попыток, сохранение JSON-ответов, проверка и начисление баллов в PL/SQL;
- общий таймер и таймер отдельного вопроса с серверной проверкой времени;
- категории, пользовательские тематики и правила вида «N вопросов категории X сложности Y»;
- статистика правильности каждого вопроса и сравнение пользователя со средним результатом;
- настраиваемая обратная связь: сразу, после теста или никогда;
- изображения вопросов и вариантов в Oracle BLOB;
- адаптивный выбор следующего вопроса: сложность повышается после верного ответа и снижается после ошибки;
- бейджи, пользовательские и командные рейтинги, мок командного квиза;
- PDF-сертификат, который PL/SQL самостоятельно формирует и сохраняет как BLOB.

- досрочное завершение: Oracle закрывает неотвеченные вопросы с нулевыми баллами, рассчитывает итог и создаёт PDF.
Подробная привязка каждого требования к коду находится в матрице соответствия (docs/requirements_matrix.md).

Архитектурная граница

flowchart TD
    UI["Оконный Tkinter-клиент"] --> AUTH["Общее соединение Oracle"]
    AUTH --> GAME["Игровой логин и пароль"]
    GAME --> API["Пакет QUIZ_PLATFORM"]
    API --> DATA["Таблицы Oracle"]
    API --> RULES["Таймеры отбор проверка"]
    API --> OUT["Статистика рейтинг PDF BLOB"]
    OUT --> UI

Python не читает правильные ответы до разрешённого момента, не сравнивает и не преобразует ответы, не вычисляет процент, не выбирает сложность и не создаёт сертификат. Клиент показывает готовый текст таймера, результата ответа и итога, полученный из Oracle. В Python нет обратного отсчёта или проверки дедлайна: решение о просрочке всегда принимает пакет. Для динамического показа Tkinter раз в секунду запрашивает новую строку таймера у Oracle, не уменьшая время локально.

Игровой пароль Python передаёт процедуре LOGIN, которая сверяет солёный SHA-256 хеш в Oracle. При регистрации REGISTER_USER сохраняет email, соль и хеш, но не открытый пароль. Все игроки используют одну учётную запись Oracle из python/.env; логин игрока задаёт отдельную игровую сессию.

Требования к среде

- Oracle Database 12c или новее, включая Oracle Database Free;
- SQL*Plus или SQLcl — только для ручного запуска .sql; автоматическому установщику они не нужны;
- Python 3.10 или новее;
- Tkinter из стандартной установки Python;
- сетевой доступ Python к Oracle Listener.

Схеме приложения нужны права CREATE SESSION, CREATE TABLE, CREATE PROCEDURE, CREATE SEQUENCE и квота на табличное пространство. Право CREATE VIEW не требуется: каталог, результаты и статистика вычисляются SQL-запросами внутри QUIZ_PLATFORM. Python только отображает полученные данные. Стандартные STANDARD_HASH, SYS_GUID, DBMS_LOB и DBMS_RANDOM используются без внешних библиотек.

Пример подготовки отдельной учебной схемы от имени администратора:

CREATE USER quiz_app IDENTIFIED BY "StrongLabPassword1!";
ALTER USER quiz_app QUOTA UNLIMITED ON users;
GRANT CREATE SESSION, CREATE TABLE, CREATE PROCEDURE, CREATE SEQUENCE TO quiz_app;

Имя табличного пространства users при необходимости замените на используемое в вашей установке.

Установка базы данных

Из корня проекта выполните:

sql quiz_app/StrongLabPassword1!@localhost:1521/FREEPDB1 @sql/install.sql

Отдельные пользователи Oracle для игроков не создаются. Игровые профили находятся в QP_USERS.

Установщик последовательно создаёт 23 таблицы, спецификацию и тело пакета, затем загружает демонстрационные данные. При ошибке скрипт завершится с ненулевым кодом. Поскольку Oracle фиксирует DDL автоматически, перед повторной установкой после частичного сбоя запустите sql/uninstall.sql.

Сразу после установки проверьте состав и статус объектов Oracle:

sql quiz_app/StrongLabPassword1!@localhost:1521/FREEPDB1 @tests/verify_install.sql

Скрипт проверяет версию Oracle, 23 таблицы, отсутствие зависимостей пакета от представлений, статус пакета,
44 публичные процедуры и демонстрационные данные. Затем выполните быстрый
сценарий всех семи типов вопросов, расчёта результата и PDF:

sql quiz_app/StrongLabPassword1!@localhost:1521/FREEPDB1 @tests/smoke_test.sql

Smoke-тест создаёт временного пользователя, проходит демонстрационный тест на
100%, проверяет заголовок %PDF, выводит три строки PASS и выполняет
ROLLBACK, поэтому его можно запускать повторно без очистки базы.

Перед защитой рекомендуется полная регрессия:

sql quiz_app/StrongLabPassword1!@localhost:1521/FREEPDB1 @tests/full_regression.sql

Она проверяет ACL игроков, семь типов вопросов, адаптивное изменение сложности,
таймер вопроса и теста, бейджи, личный и командный рейтинги, командный квиз,
разбор ответов и PDF. Все созданные ею данные также откатываются.

Запуск оконного приложения

В Windows из корня проекта один раз подготовьте окружение, затем запускайте игру:

.\SETUP_VENV.cmd
.\START_GAME.cmd

START_GAME.cmd запускает pythonw.exe, поэтому открывается только окно игры без консоли и браузера. Для диагностического запуска из терминала используйте:

python\.venv\Scripts\python.exe python\desktop_app.py

Отредактируйте python/.env перед запуском: здесь находятся данные общей учётной записи Oracle. Игровой пароль вводится в окне приложения и не записывается в этот файл:

ORACLE_USER=QUIZ_APP
ORACLE_PASSWORD=пароль_схемы
ORACLE_HOST=127.0.0.1
ORACLE_PORT=1521
ORACLE_DATABASE=FREEPDB1
ORACLE_CONNECT_MODE=SERVICE
ORACLE_SCHEMA=QUIZ_APP
ORACLE_DEMO_USER=QUIZ_STUDENT

Драйвер работает в Thin mode, поэтому локальный Oracle Client не требуется. Tkinter отвечает только за окно, поля ввода, списки и изображения. Виртуальное окружение хранится в D:\Codex\OracleQuiz\project\python\.venv, поэтому Python-пакеты не занимают место проекта на диске C:.

Демонстрационные аккаунты

| Роль | Игровой логин | Игровой пароль |
| --- | --- | --- |
| Участник | QUIZ_STUDENT | Student123! |
| Автор | QUIZ_AUTHOR | Author123! |
| Администратор | QUIZ_ADMIN | Admin123! |

Демо-пароли предназначены только для локальной лабораторной базы. Для университетского сервера укажите в python/.env общую учётную запись Oracle, а в форме подключения — хост, порт, SID либо имя сервиса. При регистрации нового игрока требуются логин, имя, email, пароль и повтор пароля. Вход выполняется по игровому логину и паролю.

Если база была установлена до появления игрового входа, обновите только пакет, сохранив все данные:

python\.venv\Scripts\python.exe upgrade_game_login.py

Для нового игрока нажмите «Зарегистрироваться» и заполните все поля отдельной формы, включая пароль и его повтор. Выберите роль «Участник» или «Автор». Автор после входа получает раздел «Конструктор» и может создавать свои тесты. Совпадение паролей и допустимую роль проверяет Oracle; после регистрации вход выполняется автоматически. Email не используется вместо логина.

Проверка без SQLcl через тот же venv:

python\.venv\Scripts\python.exe tests\registration_flow_test.py
python\.venv\Scripts\python.exe tests\oracle_auth_test.py
python\.venv\Scripts\python.exe tests\run_sql_scenario.py smoke_test.sql
python\.venv\Scripts\python.exe tests\run_sql_scenario.py full_regression.sql
python\.venv\Scripts\python.exe tests\desktop_ui_test.py

Демонстрационный сценарий

1. Войдите как участник и откройте тест «Oracle и PL/SQL: семь форматов».
2. Пройдите семь разных видов вопросов. Варианты перемешиваются один раз и остаются стабильными при перерисовке страницы.
3. Откройте результат, сравнение со средним, полученный бейдж и PDF-сертификат.
4. Пройдите «Адаптивный PL/SQL»: Oracle начинает со сложности 3 и изменяет её на один уровень после каждого ответа.
5. Создайте команду и запустите «Командный блиц»; баллы попадут и в личный, и в командный рейтинг.
6. Войдите как автор, создайте черновик, вопросы, варианты или ключи, правила генерации и ACL, затем опубликуйте тест.

Контракт ответа

Интерфейс передаёт ответ в QUIZ_PLATFORM.SUBMIT_ANSWER как JSON. Значение интерпретирует только Oracle.

| Тип | JSON |
| --- | --- |
| SINGLE, TRUE_FALSE | {"option_ids":[1]} |
| MULTIPLE | {"option_ids":[1,3]} |
| TEXT | {"text":"DUAL"} |
| NUMBER | {"number":"42"} (raw text; Oracle converts or rejects it) |
| ORDERING | {"option_ids":[11,12,13]} |
| MATCHING | {"pairs":[{"option_id":16,"answer":"42"}]} |

Доступ по игрокам

QP_TEST_ACCESS хранит игровые логины в верхнем регистре. GRANT_TEST_ACCESS проверяет существование игрового профиля в QP_USERS. При старте попытки пакет сравнивает ACL с логином владельца игровой сессии. Для публичного теста отдельная запись ACL не требуется. Имя столбца ORACLE_USERNAME сохранено ради совместимости со старой схемой, теперь оно содержит игровой логин.

PDF-сертификат

GENERATE_CERTIFICATE_INTERNAL формирует минимальный PDF 1.4, рассчитывает таблицу смещений, преобразует CLOB в BLOB через DBMS_LOB.CONVERTTOBLOB и сохраняет файл в QP_CERTIFICATES. Python получает готовые байты через GET_CERTIFICATE. Документ создаётся для каждой завершённой или прерванной попытки и содержит итоговые баллы и процент.

Стандартный встроенный шрифт Helvetica не содержит кириллицу, поэтому имя и название в автономно сформированном PDF транслитерируются. Это сохраняет независимость от внешних файлов шрифтов и от Python.
