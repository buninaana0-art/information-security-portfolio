# Матрица соответствия требованиям лабораторной работы

## Условия начала сдачи

- Не менее двух пользователей: начальная установка создаёт пять игровых аккаунтов, включая `DEMO_ALICE` и `DEMO_BOB`.
- Не менее десяти игр: у каждого из двух демонстрационных игроков по 12 завершённых игр/игр с истёкшим временем, всего 24. Покрыты обычный, адаптивный, командный режимы и все семь типов вопросов.
- Данные поставляются со схемой: `sql/install.sql` запускает `06_demo_history.sql`, затем `tests/verify_demo_history.sql` проверяет пользователей, режимы, ответы и сертификаты.
- Новый компьютер: `INSTALL_AND_RUN.cmd` устанавливает недостающие компоненты, создаёт БД и `venv`, проверяет данные и запускает оконный клиент. Для готовой базы вуза используется `INSTALL_UNIVERSITY_SERVER.cmd`; дополнительные параметры не нужны.

## Оценка 3

| Требование | Реализация и место проверки |
| --- | --- |
| Конструктор тестов | `CREATE_TEST`, `ADD_QUESTION`, `ADD_ANSWER_OPTION`, `ADD_QUESTION_KEY`; раздел «Конструктор» в `python/desktop_app.py`. |
| Один, несколько и текстовый ответ | Коды `SINGLE`, `MULTIPLE`, `TEXT` в `QP_QUESTION_TYPES`; ветви `SCORE_RESPONSE`. |
| Доступ по списку игроков | `QP_TEST_ACCESS`, `GRANT_TEST_ACCESS`, проверка игрового логина в `QP_USERS`, `CAN_ACCESS_TEST` и проверка перед `START_ATTEMPT`. |
| Регистрация попытки и ответов | `QP_ATTEMPTS`, `QP_ATTEMPT_QUESTIONS`, `QP_RESPONSES`; процедуры `START_ATTEMPT`, `SUBMIT_ANSWER`. |
| Подсчёт баллов | `SCORE_RESPONSE`, `RECALCULATE_RESULT_INTERNAL`; Python не выполняет арифметику результата. |
| Граница Python/Oracle | Python сериализует поля формы и отображает готовые строки Oracle. Проверка ответа, дедлайна, результата, сложности и проходного порога находится только в `QUIZ_PLATFORM`; это дополнительно контролирует `tests/run_static_checks.py`. |
| Результат и список попыток | `GET_ATTEMPT_RESULT`, `GET_MY_ATTEMPTS`. |

## Оценка 4

| Требование | Реализация и место проверки |
| --- | --- |
| Таймер теста | `QP_ATTEMPTS.DEADLINE_AT`, `EXPIRE_DUE_STATE`; проверяется при каждом чтении вопроса и сохранении ответа. |
| Таймер вопроса | `QP_ATTEMPT_QUESTIONS.DEADLINE_AT`; просроченный активный вопрос получает `TIMED_OUT` и 0 баллов. |
| Сложность и категории | `QP_QUESTIONS.DIFFICULTY_LEVEL`, `CATEGORY_ID`. |
| N вопросов категории X сложности Y | `QP_TEST_RULES`; случайная серверная выборка при `START_ATTEMPT`. |
| Анализ по вопросам | `SHOW_STATISTICS`: число показов, ответов, процент правильных и среднее время. |
| Сравнение со средними | `GET_USER_COMPARISON`: средний процент, отклонение, место и число участников. |
| Настройка обратной связи | `FEEDBACK_MODE`, `SHOW_CORRECT_ANSWERS`, `GET_ATTEMPT_FEEDBACK`; до разрешённого момента эталоны не возвращаются. |
| Минимум 6 типов | Реализовано 7 типов: `SINGLE`, `MULTIPLE`, `TEXT`, `TRUE_FALSE`, `NUMBER`, `ORDERING`, `MATCHING`. |

## Оценка 5

| Требование | Реализация и место проверки |
| --- | --- |
| Тематики пользователя | `QP_TOPICS`, `QP_TEST_TOPICS`, `CREATE_TOPIC`, `ADD_TEST_TOPIC`, фильтр каталога. |
| Изображения | `IMAGE_DATA BLOB` у вопросов и вариантов; `SET_QUESTION_IMAGE`, `SET_OPTION_IMAGE`; показ обоих видов изображений в оконном Tkinter-клиенте. |
| Адаптивное тестирование | `CURRENT_DIFFICULTY`; `GET_NEXT_QUESTION` выбирает неиспользованный вопрос с ближайшей сложностью, `SUBMIT_ANSWER` изменяет уровень ±1. |
| Бейджи | `QP_BADGES`, `QP_USER_BADGES`, структурированные правила и `ASSIGN_BADGES_INTERNAL`. |
| Публичные рейтинги | `QP_RATING_SNAPSHOTS`, `REBUILD_RATINGS_INTERNAL`, `GET_LEADERBOARD` для недели, месяца и всего периода. |
| Командные квизы | `QP_TEAMS`, `QP_TEAM_MEMBERS`, привязка попытки к команде и отдельный рейтинг `TEAM`; мок без синхронного real-time раунда. |
| PDF-сертификат | PDF 1.4 генерируется в `MAKE_CERTIFICATE_PDF`, хранится в `QP_CERTIFICATES.PDF_DATA`, скачивается без генерации в Python. |

## Дополнительные свойства качества

| Свойство | Реализация |
| --- | --- |
| Пароли | Индивидуальная соль и SHA-256 через `STANDARD_HASH`; открытый пароль не сохраняется. |
| Регистрация и вход | Одна общая учётная запись Oracle для соединения; `REGISTER_USER` принимает игровой логин, пароль, повтор пароля, имя, email и роль `PARTICIPANT` либо `AUTHOR`. Совпадение паролей, допустимую роль и вход проверяет Oracle. Новый автор может создавать тесты; публичная регистрация администратора запрещена. |
| Сессии | Случайный 64-символьный токен, срок 8 часов, отзыв предыдущей активной сессии. |
| Целостность | Первичные и внешние ключи, `CHECK`, уникальные индексы, каскадное удаление только зависимых сущностей. |
| Защита от подмены вопроса | `SUBMIT_ANSWER` принимает только текущий активный вопрос данной попытки. |
| Защита правильных ответов | Курсор игрового вопроса не содержит `IS_CORRECT`, `CORRECT_ORDER`, `MATCH_KEY` или ключи текста. |
| Стабильность интерфейса | `QP_ATTEMPT_OPTIONS` фиксирует случайный порядок вариантов на всю попытку. |
| Аудит | `QP_AUDIT_LOG` фиксирует вход, создание, публикацию, ответы, завершение и изменение ACL. |
| Воспроизводимая проверка | `verify_install.sql` проверяет установку; `smoke_test.sql` — семь типов, 100-процентный результат и PDF; `full_regression.sql` — ACL, адаптацию, таймеры, бейджи, рейтинги и командный режим. Все функциональные тесты выполняют `ROLLBACK`. |
